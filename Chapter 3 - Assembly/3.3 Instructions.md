# 3.3 命令(Instructions)

アセンブリコードを読んで理解する能力は、リバースエンジニアリングに不可欠です。命令はおよそ 1,500 個ありますが、その大半は一般的にはあまり使われないか、(MOV と MOVS のような)単なるバリエーションです。高水準のプログラミングと同じように、知らないことは遠慮せずに調べてください。

始める前に、知っておくべき 3 つの用語があります。**イミディエイト(immediate)**、**レジスタ(register)**、**メモリ(memory)**です。

* **イミディエイト値**(または単にイミディエイト、IM と呼ぶこともあります)は、数値 12 のようなものです。イミディエイト値はメモリアドレスやレジスタでは*なく*、何らかの定数データです。
* **レジスタ**は、RAX、RBX、R12、AL などのものを指します。
* **メモリ**または**メモリアドレス**は、0x7FFF842B のような、メモリ内の場所(メモリアドレス)を指します。

> いくつかのアセンブリ命令の末尾や途中に、セミコロンが付いていることがあります。これは、アセンブリではセミコロン(;)がコメントを書くために使われるからです。

命令の書式を知っておくことは重要で、次のとおりです:  
**(命令/オペコード/ニーモニック) \<デスティネーションオペランド\>, \<ソースオペランド\>**  
> 命令/オペコード/ニーモニックを、ここでは命令と呼びます。人によって呼び方が違うことに注意してください。

例:

```asm
mov RAX, 5
```

MOV が命令、RAX がデスティネーションオペランド(destination operand)、5 がソースオペランド(source operand)です。命令やオペランドの大文字と小文字は関係ありません。すべて大文字のものと、すべて小文字のものが混在して使われます。この例では、5 は有効なメモリアドレスではなく、もちろんレジスタでもないので、イミディエイト値です。

## 一般的な命令

## データ

**MOV** は、ソースオペランドをデスティネーションに移動/格納するために使います。ソースは、次の例のようにイミディエイト値である必要はありません。次の例では、イミディエイト値の 5 が RAX に移動されます。  
**これは RAX = 5 と同じです。**

```asm
mov RAX, 5
```

**LEA** は Load Effective Address(実効アドレスのロード)の略です。アドレスを対象にする点を除いて、基本的に MOV と同じです。アドレスの計算にもよく使われます。次の例では、RAX に num1 のメモリアドレス/場所が入ります。

```asm
lea RAX, num1
```

**PUSH** は、データをスタックにプッシュするために使います。プッシュとは、スタックの一番上に何かを置くことです。次の例では、RAX がスタックにプッシュされます。プッシュはコピーとして動作するので、RAX にはプッシュされる前の値が残ります。

```asm
push RAX
```

**POP** は、スタックの一番上にあるものを取り出して、デスティネーションに格納するために使います。次の例では、スタックの一番上にあるものが RAX に入ります。

```asm
pop RAX
```

### 算術

**INC** はデータを 1 だけインクリメントします。次の例では、RAX を 8 に設定し、それをインクリメントします。最終的に RAX は 9 になります。

```asm
mov RAX, 8
inc RAX
```

**DEC** は値をデクリメントします。次の例では、RAX は最終的に 7 になります。

```asm
mov RAX, 8
dec RAX
```

**ADD** は、ソースをデスティネーションに加算し、結果をデスティネーションに格納します。次の例では、RAX に 2、RBX に 3 を移動し、それらを足し合わせます。結果(5)は RAX に格納されます。  
RAX = RAX + RBX または RAX += RBX と同じです。

```asm
mov RAX, 2
mov RBX, 3
add RAX, RBX
```

**SUB** は、デスティネーションからソースを減算し、結果をデスティネーションに格納します。次の例では、RAX は最終的に 2 になります。  
RAX = RAX - RBX または RAX -= RBX と同じです。

```asm
mov RAX, 5
mov RBX, 3
sub RAX, RBX
```

**MUL**(符号なし)または **IMUL**(符号付き)は、デスティネーションにソースを掛けます。結果はデスティネーションに格納されます。IMUL は符号付き、MUL は符号なしに使います。次の例では、RAX は最終的に 15 になります。

```asm
mov RAX, 5
mov RBX, 3
mul RAX, RBX
```

**DIV**(符号なし)または **IDIV**(符号付き)。- いずれ(たぶん)ここに自分の説明を書きます。今のところは、次のリンクを参照してください:

* **DIV**: <https://www.felixcloutier.com/x86/div>
* **IDIV**: <https://www.felixcloutier.com/x86/idiv>

### フロー

**CMP** は 2 つのオペランドを比較し、結果に応じて適切なフラグを設定します。次の例では、ゼロフラグ(ZF)が 1 に設定され、これは比較によって RAX が 5 に等しいと判定されたことを意味します。フラグについては、次のレッスン [3.4 Flags](3.4%20Flags.md) で説明します。

```asm
mov RAX, 5
cmp RAX, 5
```

**JCC** 命令は、現在設定されているフラグに基づいてジャンプする条件付きジャンプです。JCC は命令ではなく、JNE、JLE、JNZ など多くの命令を含む命令群です。JNE は等しくなければジャンプ(jump if not equal)、JLE は以下ならジャンプ(jump if less than or equal)です。これは if 文でよく使われます。次の例では、RAX が 5 に等しくなければ、すぐに終了します。5 に等しければ、RBX を 10 に設定してから終了します。

```asm
mov RAX, 5
cmp RAX, 5
jne 5       ; 等しくなければ 5 行目 (ret) へジャンプする。
mov RBX, 10
ret
```

**RET** は return の略です。実行を前の関数に戻します。次の例では、RAX を 10 に設定してから戻ります。

```asm
mov RAX, 10
ret
```

**NOP** は No Operation の略です。この命令は事実上何もしません。通常は、パディングに使われます。パディングを行うのは、コードの一部が 16 ビット境界や 32 ビット境界のような特定の境界に置かれることを好むからです。

## 3.1 の例に戻る

3.1 の例を覚えていますか? こちらです:

```c
if(x == 4){
    func1();
}else{
    return;
}
```

は、次と同じです

```assembly
mov RAX, x
cmp RAX, 4
jne 5       ; 5行目 (ret)
call func1
ret
```

これで、アセンブリ版を自力で読み解けるようになったと思います。変数 `x` を RAX に移動し、`x` を 4 と比較します。*等しくなければ*戻り、*等しければ* "func1" を呼び出します。

## 反転

上の例では、比較が反転していることにも気づくかもしれません。  
次の代わりに

```c
if(x == 4){
    func1();
}else{
    return;
}
```

アセンブリ版は次のようになっています:

```c
if(x != 4){
    return;
}else{
    func1();
}
```

アセンブリ版を、元の C 版に合わせることも簡単にできます。例で示したアセンブリは、「実際の現場」で通常目にするものです。そうは見えないかもしれませんが、その理由は効率です。基本的に、コンパイラーはプログラムを、主に次の 2 通りのどちらかの形にできます:

```assembly
mov RAX, x
cmp RAX, 4
je 5       ; 5行目 (call func1)
ret
call func1
ret
```

```assembly
mov RAX, x
cmp RAX, 4
jne 5       ; 5行目 (ret)
call func1
ret
```

このコードは、`func1` が戻ったときや、RAX が 4 に等しくないときに、戻りたいのです。言い換えると、どちらの場合でも戻ります。命令の数を減らすために、コンパイラーは 2 番目の選択肢を選びます。`if(x == 4)` の代わりに `if(x != 4)` に近い形で if 文を書くプログラマーを見たことがあるかもしれませんが、おそらくこれが理由です。とはいえ、コンパイラーはたいていの場合どのみち最適なものを選ぶので、プログラマーがどう書くかは実はあまり関係ありません。

## ポインタ

アセンブリにも、C/C++ と同じように、ポインタやメモリアドレスを扱う方法があります。C/C++ では、デリファレンス(dereferencing)を使って、メモリアドレスの中の値を取得できます。例:

```c
int main(){
    int num = 10;
    int* ptr = &num;        //y は x のアドレスになった
    /* 
    ptr is dereferenced so it prints what's inside of the address 
    that it's holding. The value inside of the address that it's 
    holding is 10.
    */
    printf("%d", *ptr);   
}
```

アセンブリでポインタやアドレスを扱うときに知っておくべき最も重要なことの 2 つは、**LEA** と**角括弧(square brackets)**です。  

* **角括弧** - 角括弧は「指し示されているアドレス」を表します。たとえば、`[var]` は var が指すアドレスです。言い換えると、`[var]` を使うときは、`var` が保持しているメモリアドレスにアクセスしたいということです。
* **LEA** - LEA を扱うときは、角括弧に関することを文字どおりすべて無視してください。LEA は Load Effective Address の略で、アドレスの計算とロードに使われます。

**LEA 命令を扱うとき、角括弧はデリファレンス*しない*ことに注意することが重要です。**  
**LEA 命令を扱うとき、角括弧はデリファレンス*しない*ことに注意することが重要です。**  
**LEA 命令を扱うとき、角括弧はデリファレンス*しない*ことに注意することが重要です。**  
十分に言ったでしょうか? これで混乱しないでください。LEA が角括弧に関するルールを破ることを知らない人は、すぐにひどく混乱します。LEA はアドレスをロードして計算するためのもので、データではありません。角括弧があってもなくても関係なく、アドレスだけを扱います。LEA は多くの人の頭を混乱させがちです。彼女に惑わされないでください。  

アセンブリでの、デリファレンスとポインタの簡単な例を示します:

```assembly
lea RAX, [var]
mov [RAX], 12 
```

上の例では、`var` の<u>*アドレス*</u>が RAX にロードされます。ここで扱っているのは LEA なので、デリファレンスは*<u>ありません</u>*。RAX は、本質的にポインタになりました。次に、RAX が保持するアドレス(RAX が指すアドレスと言われることが多いです)に 12 が移動されます。RAX が指すアドレスは `var` 変数です。このアセンブリが実行されると、`var` は 12 になります。  

先ほど、LEA はアドレスの計算に使えると言いましたが、実際によく使われます。

```assembly
lea RAX, [RCX+8]    ;RAX に RCX+8 のアドレスを設定する。
```

```assembly
mov RAX, [RCX+8]    ;RAX に RCX+8 の中の値を設定する。
```

もう一度言います:  
**LEA を扱うとき、角括弧はデリファレンス*しない*ことに注意することが重要です。**  
LEA と MOV はしょっちゅう使われるので、必ず理解しておいてください。少し分かりにくいことは承知していますが、LEA はアドレス用だということを覚えておいてください。
