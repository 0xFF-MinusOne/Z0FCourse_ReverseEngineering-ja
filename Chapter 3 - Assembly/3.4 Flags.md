# 3.4 フラグ(Flags)

さまざまな理由で使われるフラグが数多くあります。すでに説明したフラグの 1 つが、ゼロフラグ(ZF)です。

## ステータスフラグ

知っておくべきフラグは次のとおりです。「フラグがセットされる」と言うときは、フラグが 1(真/オン)に設定されることを意味します。0 は偽/オフです。

* **ゼロフラグ(Zero Flag、ZF)** - 演算結果がゼロの場合にセットされます。演算結果がゼロ*でない*場合はセットされません。
* **キャリーフラグ(Carry Flag、CF)** - 直前の*符号なし*算術演算で、レジスタの範囲を超えて桁上がり(加算)または桁借り(減算)があった場合にセットされます。このフラグは符号なし、つまり正の数だけを対象とするため、演算結果が負の場合にもセットされます。負の数は、非常に大きな正の数である可能性があるからです。
* **オーバーフローフラグ(Overflow Flag、OF)** - *符号付き*算術演算の結果が、レジスタに収まらないほど大きい場合にセットされます。
* **サインフラグ(Sign Flag、SF)** - 演算結果が負の場合にセットされます。
* **調整/補助フラグ(Adjust/Auxiliary Flag、AF)** - キャリーフラグと同じですが、2 進化 10 進数(Binary Code Decimal、BCD)の演算用です。
* **パリティフラグ(Parity Flag、PF)** - 下位 8 ビットでセットされているビットの数が偶数の場合に 1 になります。(10110100 なら PF=1、10110101 なら PF=0)
* **トラップフラグ(Trap Flag、TF)** - プログラムのシングルステップ実行を可能にします。

フラグの完全な一覧は、こちらを見てください: <https://www.tech-recipes.com/rx/1239/assembly-flags/>

## 例

### 基本的な比較

フラグを示す例をいくつか挙げます。

次の例で最も重要なフラグは、ゼロフラグ(ZF)です。このコードは、RAX が 4 に等しいかどうかを判定しようとしています。2 行目に CMP 命令があり、結果に応じてフラグを設定します。この場合、RAX は 4 に等しいので、ZF が 1 に設定されます。JNE 命令は、フラグを見て、直前の演算で ZF がセットされたかどうかを確認します。

```assembly
mov RAX, 4
cmp RAX, 4
jne 5       ; 5行目 (ret)
call func1
ret
; ZF = 1, OF = 0, SF = 0
```

### 減算の結果が負になる場合

次は*符号付き*演算の場合です。減算の結果が負の数になったので、SF フラグが 1 に設定されます。SUB 命令を使った場合も、両者は(基本的に)同じことをするので、同じになります。

```assembly
mov RAX, 2
cmp RAX, 8  ; 2 - 8 = -6.
; ZF = 0, OF = 0, SF = 1
```

次は、結果が大きすぎてレジスタに収まらない例です。ここでは小さな数で扱えるように、8 ビットレジスタを使っています。符号付き 8 ビットレジスタに収まる最大の数は 128 です。AL に 75 をロードし、そこに 60 を加算します。2 つを足した結果は 135 になるはずですが、保持できる最大の数は 128 です。このため、数値は折り返され、AL は -121 になります。結果がレジスタに対して大きすぎたので OF がセットされ、結果が負なので SF フラグがセットされます。これが符号なし演算であれば、CF がセットされます。

```assembly
mov AL, 75
add AL, 60
; ZF = 0, OF = 1, SF = 1
```

## 最後に

これで、フラグとは何か、どのように働くかが、よく分かったと思います。CMP は比較の結果に応じてフラグを設定することを覚えておいてください。条件付きジャンプは、単にフラグを見ます。つまり、条件付きジャンプが動作するために、直前に CMP が必要なわけではありません。また、フラグは CMP 命令以外によってもセットされます。
