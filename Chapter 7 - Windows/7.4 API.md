# Windows API

ソフトウェアをリバースしていると、OS が導入した機能にたくさん出会います。結局のところ、ほとんどすべては Windows API の呼び出しに行き着きます。そのため、Windows API を見分けて理解することは非常に重要です。ここでは、API の一部、その仕組み、命名規則、そして API の理解を深めるのに役立つ共通のテーマを紹介します。

Windows API を理解することは、特に OS と低レベルで作業したい場合に、非常に強力な武器になります。私は、メモリの読み書き、プロセスの列挙、システムの列挙、レジストリの操作、ネットワークなど、OS レベルの概念を扱うツールやプログラムを数多く自作しています。

## WOW64

WOW64 は Windows のサブシステムで、Windows 32 on Windows 64 の略です。64ビット版 Windows の重要な部分です。

64ビット版の Windows には、OS に同梱されたさまざまな OS の DLL やプログラムを含む、重要な OS ディレクトリが2つあります。それが C:\Windows\System32 と C:\Windows\SysWOW64 です。これらのディレクトリを見ると、中身がほぼ同じであることが分かります。この2つのディレクトリが存在する理由は、下位互換性とソフトウェアの実行のためです。プログラムがシステム DLL を参照すると、その2つの場所のどちらかから取得します。どちらのディレクトリを探すかは、32ビットのプログラムか64ビットのプログラムかによって決まります。ここが少し奇妙なところです。

64ビット版 Windows では次のようになっています。

* 32ビットの DLL は C:\Windows\SysWOW64 にあります
* 64ビットの DLL は C:\Windows\System32 にあります

プログラムがシステム DLL を読み込もうとするとき、デフォルトの場所は System32 です。これは64ビットでも32ビットでも同じです。32ビットの DLL は SysWOW64 にあるので、32ビットのプログラムで問題が起こりえます。WOW64 は、32ビットプログラムの要求を System32 から SysWOW64 にリダイレクトします。想像できると思いますが、これは WOW64 が行うことのほんの一部です。ここでの目的には、WOW64 が存在することと、おおまかに何をするかを知っていれば十分です。ただし、これは非常に興味深いトピックで、内部の仕組みを知っていれば役立つこともあります。さらに調べたい場合の出発点を、ここに示します。

<https://docs.microsoft.com/en-us/archive/msdn-magazine/2006/may/x64-starting-out-in-64-bit-windows-systems-with-visual-c>

## API Usage(API の使い方)

WOW64 の話が済んだので、Windows API(WinAPI)に戻りましょう。WinAPI には、考えられるほぼすべてのことのための機能があります。前に述べたように、OS に対して何かをしたい場合は、最終的に必ず必要になります。Windows API は広大なので、最も重要なものだけを取り上げます。API のさまざまなコンポーネントを、自分でざっと見ておくことを強くお勧めします。

取り上げませんが、自分で学ぶと役立つかもしれない API のトピックは次のとおりです。

* グラフィックス(DWM、GDI など)
* ユーザー入力
* フック(プロセスのエクスプロイト/操作で知っておくととても役立つかもしれません)
* PnP

取り上げるものは次のとおりです。

* 一般的な用語(命名規則、傾向、データ型など)
* ファイル I/O
* レジストリ
* ソケット(ネットワーク)
* プロセス
* スレッド
* メモリ
* サービス

さらに調べるのに適した場所はこちらです。
<https://docs.microsoft.com/en-us/windows/win32/apiindex/windows-api-list>

## General Terminology(一般的な用語)

* 関数の命名規則:
  * A - ASCII。文字エンコーディングに ASCII を使用し、1文字あたり1バイトです。
  * W - Wide。関数はワイド文字エンコーディング、つまり2バイトの Unicode を使用します。
  * Ex(CopyFileEx など)- Extended(拡張)。以前の関数を作り直した/再開発したバージョンです。ほかの関数との互換性を保つために、名前を変えて更新した関数と考えてください。名前を変えずに関数を変更すると、変更が現在のプログラムに悪影響を及ぼすおそれがあります。
