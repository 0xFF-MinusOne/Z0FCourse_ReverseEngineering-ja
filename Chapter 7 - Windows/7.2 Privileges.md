# 7.2 Privileges(特権)

OS の重要なコンポーネント、データ、プロセスを保護するために、プロセッサが動作できる特権モードは2つあります。**ユーザーモード**(user-mode)と**カーネルモード**(kernel-mode)です。ユーザーのコードはユーザーモードで動作し、OS のコード(ドライバを含む)はカーネルモードで動作します。

> 4つの異なる特権レベルが、リング(0から3の番号)として説明されるのを聞いたことがあるかもしれません。ユーザーモードは特権レベル/リング3で、カーネルモードは特権レベル/リング0です。リング1と2は Windows では使われません。

## Kernel-Mode(カーネルモード)

**カーネルモード**では、システム上のあらゆるコードへのアクセスが許されるため、プロセッサは基本的に何でも好きなことができます。ユーザーモードのプロセスは、厳密に定義されたインターフェースを通じてしかカーネルにアクセスできません。カーネルモードは、ユーザーモードのプロセスを統制しておくために OS に必要なものです。カーネルモードのプロセスは同じ仮想アドレス空間を共有します。カーネルモードの仮想アドレス空間内のページには、カーネルモードからしかアクセスできません。ユーザーモードのページには、カーネルモードとユーザーモードの両方からアクセスできます。

## User-Mode to Kernel-Mode(ユーザーモードからカーネルモードへ)

ユーザーモードのプロセスが、カーネルモードの機能にアクセスする必要があることがあります。ウィンドウやグラフィックスを描画するときなど、これはとても頻繁に起こります。ユーザーモードのプロセスがシステムサービスを呼び出すと、スレッドをカーネルモードに切り替える特別な命令が実行されます。サービスが終了すると、スレッドはユーザーモードに戻されます。

**ユーザーモードのコードは、メモリ範囲 0x00000000 から 0x7FFFFFFF で動作します。**
**カーネルモードのコードは、メモリ範囲 0x80000000 から 0xFFFFFFFF で動作します。**

## Hypervisor(ハイパーバイザ)

仮想化の隆盛とともに、高性能な OS ゲストを効率よく動かす方法が必要になりました。この仮想化を実現するために、ハイパーバイザ(hypervisor)が使われます。**ハイパーバイザ**は、仮想メモリ、物理メモリ、USB デバイスなど、システムのすべてのコンポーネントを分離・隔離できるようにします。ハイパーバイザは、コンポーネントを仮想化・隔離できるため、カーネルモードのアプリケーションよりも多くの特権と能力を持ちます。このため、Windows はセキュリティにハイパーバイザを使っており、これは*仮想化ベースのセキュリティ*(virtualization-based security、VBS)として知られています。VBS のコンポーネントには、Hyper Guard、Credential Guard、Application Guard、Host Guardian、Shielded Fabric などがあります。これらすべてのコンポーネントは説明しませんが、そのうち2つを簡単に説明します。

* **Hyper Guard** - 重要なカーネルとハイパーバイザ関連のデータ構造およびコードを保護します。
* **Application Guard** - Microsoft Edge 用のより強力なサンドボックス。

ハイパーバイザは、**仮想トラストレベル(Virtual Trust Levels、VTL)**も実装します。
> VTL の順序は、プロセッサの特権レベル(リング)とは異なります。VTL 0 の特権は VTL 1 より低いです。

OS は VTL 0 で動作し、VBS は VTL 1 で動作します。これにより、VBS にはカーネルモードより高い特権が与えられ、そのためカーネルモードからは触れられません。ユーザーモードとカーネルモードは VTL の中で動作し、ハイパーバイザがすべての VTL の権限を管理していると考えることができます。

ハイパーバイザは極めて複雑で、学ぶことがたくさんあります。ここで示した説明は、非常に簡潔で基本的なものです。それでも、リバースに関しては、知る必要があるよりも多い内容ですので、すべてを理解できなくても心配はいりません。ハイパーバイザは非常に興味深く、セキュリティにとって不可欠なので、さらに学ぶことをお勧めします。

> ハイパーバイザはカーネルモードより多くの特権を持ちますが、ハイパーバイザはリング -1 では動作*しません*。
