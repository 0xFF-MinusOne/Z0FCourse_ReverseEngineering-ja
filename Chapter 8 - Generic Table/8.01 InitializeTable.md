# 8.01 Initialize Table

リバースするときは、全体像に注目するのが最善です。関数名から、「Generic Table」はおそらく何らかのデータ構造だと推測して問題ないでしょう。また、これが「generic(汎用的な)」データ構造であることにも注意が必要です。

名前だけから分かる情報を踏まえると、まず初期化関数を見るのが良さそうです。そうすれば、テーブルに何が含まれているか、要素がいくつあるか、どんな初期値があるかが分かってくるはずです。

#### `RtlInitializeGenericTable` の逆アセンブル

```asm
LEA RAX, QWORD PTR DS:[RCX + 0x8]
XOR R10D, R10D
MOV QWORD PTR DS:[RCX], R10
MOV QWORD PTR DS:[RAX + 0x8], RAX
MOV QWORD PTR DS:[RAX], RAX
MOV QWORD PTR DS:[RCX + 0x18], RAX
MOV RAX, QWORD PTR SS:[RSP + 0x28]
MOV QWORD PTR DS:[RCX + 0x40], RAX
MOV QWORD PTR DS:[RCX + 0x20], R10
MOV QWORD PTR DS:[RCX + 0x28], RDX
MOV QWORD PTR DS:[RCX + 0x30], R8
MOV QWORD PTR DS:[RCX + 0x38], R9
RET 
```

この関数は、通常のように RSP から引いていないことに注目してください。これは、関数にローカル変数がないためです。

RCX、RDX、R8、R9 がすべて使われています。つまり、この関数は少なくとも4つのパラメータを取ります。
RCX は、使われ方から、何らかのデータ構造だとすぐに分かります。データ構造は、ベースアドレス(この場合は RCX)にオフセット(+0x40 など)を足して参照することを思い出してください。この関数の最初のパラメータはおそらく generic table ですが、簡単のため、単にテーブルと呼ぶことにします。RCX+0x28 も使われていますが、これはこの場合、5番目のパラメータです。

>「DS」は Data Segment(データセグメント)の略です。無視して構いません。

## Parameter Types(パラメータの型)

これで、関数が5つのパラメータを取ることが分かりましたが、その型は何でしょうか。最初のパラメータ RCX はおそらく generic table です。RDX、R8、R9 はすべてとてもよく似ています。いずれも `MOV QWORD PTR DS:[RCX + OFFSET], RDX/R8/R9` を使っています。これは、これらのパラメータが8バイト/64ビット(QWORD)のポインタであることを示しています。かなり大まかなデータ型ですが、今のところ分かるのはこれだけです(何もないよりはましです)。

## Data(データ)

データ構造に何が移されているかを分析しましょう。これまでの観察から、RCX にあるデータ構造はクラスか構造体だと考えて差し支えありません。ただし、間違っている場合に備えて、柔軟に考えておいてください。たとえば、一連の関数で管理される凝った配列かもしれません。

* 最初の行は、テーブルの2番目のメンバーのアドレス(RCX+0x8)を RAX に渡します。
* R10 をゼロにします。
* R10(0)を最初のメンバー(RCX)に移します。RCX はテーブルの最初のメンバー(テーブルを参照するのに使うアドレスでもあります)です。
* 次に RAX(2番目のメンバー)を RAX+0x8 にある要素に移します。RAX にはすでに RCX+0x8 が入っているため、これは3番目のメンバーです。これは実質的に RCX+0x8+0x8、つまり RCX+0x10 です。
* 次に、RAX が保持しているアドレス(2番目のメンバー)を、データ構造の2番目のメンバー(RCX+0x8 を保持している RAX)に移します。
* 次に RAX を RCX+0x18 にある要素、つまり4番目の要素に移します。

先に進む前に、少しまとまりがありませんでした。理解を助けるために、アセンブリを C のコードと対応させてみましょう。

```asm
LEA RAX, QWORD PTR DS:[RCX + 0x8]
XOR R10D, R10D
MOV QWORD PTR DS:[RCX], R10         ;Struct->Member1 = 0;
MOV QWORD PTR DS:[RAX + 0x8], RAX   ;Struct->Memeber3 = &Struct->Member2;
MOV QWORD PTR DS:[RAX], RAX         ;Struct->Memeber2 = &Struct->Member2;
MOV QWORD PTR DS:[RCX + 0x18], RAX  ;Struct->Memeber4 = &Struct->Member2;
```

メンバー2から4を見てください。すべてポインタです。いずれも2番目のメンバーのアドレスに初期化されています。これにはいくつかの意味が考えられます。単にポインタを有効なアドレスに初期化する方法で、特別なことは何もないのかもしれません。すべてに何らかの関係がある可能性もあります。たとえば、`Member2` が構造体を指し、ほかのメンバーがその構造体内の何かを指しているのかもしれません。まだ確信は持てませんが、関連していると推測しています。メンバーがどう使われるかに注目しておけば、答えが見つかるかもしれません。

先へ進みましょう。`MOV RAX, QWORD PTR SS:[RSP + 0x28]` から再開します。

* 5番目の関数パラメータ(RSP + 0x28)を RAX に渡します。
* RAX を9番目の要素に移します。
* R10(0)を5番目の要素に移します。
* RDX を6番目の要素に移します。
* R8 を7番目の要素に移します。
* R9 を8番目の要素に移します。

もう一度、アセンブリを C と比較します。

```asm
MOV RAX, QWORD PTR SS:[RSP + 0x28]
MOV QWORD PTR DS:[RCX + 0x40], RAX  ;Struct->Member9 = Param5
MOV QWORD PTR DS:[RCX + 0x20], R10  ;Struct->Member5 = 0
MOV QWORD PTR DS:[RCX + 0x28], RDX  ;Struct->Member6 = Param2
MOV QWORD PTR DS:[RCX + 0x30], R8   ;Struct->Member7 = Param3
MOV QWORD PTR DS:[RCX + 0x38], R9   ;Struct->Member8 = Param4
RET 
```

## Bringing the Information Together(情報をまとめる)

テーブルには(分かっている限り)9つのメンバーがあります。2番目、3番目、4番目のメンバーはすべて、2番目のメンバーへのポインタだと分かっています。メンバー1と5はゼロに初期化されます。各メンバーが8バイトで、メンバーが9つあることから、テーブルのサイズは72バイトと結論づけられます。また、最後のオフセットが 0x40 なので、データは合計 0x48 バイトであり、したがって72バイトだとも判断できます。

>0x40 バイトではなく 0x48 バイトのデータになるのは、現時点で分かる限り、最後の要素(オフセット 0x40)のサイズが8バイトだからです。したがって、合計サイズは 0x40 + 0x8 です。

この情報で、テーブルについて少し理解できました。テーブルの基礎的なレイアウトも組み立てられます。

```c
struct Table{
    UNKNOWN Member1;
    UNKNOWN_PTR Member2;
    UNKNOWN_PTR Member3;
    UNKNOWN_PTR Member4;
    UNKNOWN Member5;
    UNKNOWN Member6;
    UNKNOWN Member7;
    UNKNOWN Member8;
    UNKNOWN Member9;    
};
```

この関数は以上です。かなり小さく、単純で、楽しく、そして重要でした。
