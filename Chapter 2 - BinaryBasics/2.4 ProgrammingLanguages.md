# 2.4 プログラミング言語

プログラミング言語には、Python、Java、C、C++、C#、JavaScript、PHP、Lua、F#、Ruby、Go、アセンブリ、Fortran、COBOL など、数多くあります。NodeJS や Ruby on Rails のような言語のバリエーションもあります(NodeJS は JavaScript、Ruby on Rails は Ruby のフレームワークです)。言語にはレベルの高いものと低いものがあります。レベルが高いほどハードウェアから遠く、一般に人間にとって読み書きしやすくなります。たとえば、C# は非常に高水準の言語で、アセンブリは低水準の言語です。C/C++ は高水準と見なされますが、Java などよりはずっと低水準です。

## 用途の違い

言語ごとに、使われる作業や動作が異なります。JavaScript はウェブアプリケーション、C/C++ はソフトウェア、Python はスクリプトに使われます。もちろん、これらの言語はほかの用途にも使えます。たとえば、Python でウェブサイトを作ることもできます(Python で作れないものがあるでしょうか?)。

### 実行方式の違い

言語には大きく 2 種類あります。**コンパイル型(compiled)**と**インタープリター型(interpreted)**です。

* **コンパイル型の言語**は、ネイティブのマシンコードに直接コンパイル/変換されます。つまり、そのコンピューター向けにコンパイルされていれば、どのコンピューターでもプログラムを直接実行できます。コンパイルされたプログラムの利点は、たいていの場合、実行のために追加のプログラムが要らないことです。たとえば、Java プログラムを実行するには、まず **Java Runtime Environment (JRE)** をインストールする必要があります。しかし、C++ プログラムを実行するのに、JRE のようなものは要りません。ただし、コードのライブラリをダウンロードしてインストールする必要はあるかもしれません。  
* **インタープリター型の言語**は、マシンコードに直接コンパイルされるのではなく、ソースコードから*間接的に*マシンコードへ解釈/変換される言語です。この解釈は、コードの一部分、あるいは 1 行ずつをコンパイルして、その部分を実行する形で行われることがあります。たとえば、Python プログラムを実行すると、各行が基本的にコンパイルされてから個別に実行されます(これは厳密には正しくありませんが、要点は伝わります)。この方式の利点は、特定のシステム向けにプログラムを書き直したりコンパイルしたりする必要がないことです。ユーザーは、適切な追加ソフトウェアをインストールするだけで、あなたのソフトウェアを実行できます。最大の欠点は、コンパイル型の言語より*はるかに*遅くなりがちなことです。  
解釈のもう 1 つの形は、バイトコードのような中間物を使う方法です(次に説明します)。

#### 中間言語

中間言語について話しておくことは非常に重要です。Java を例にしましょう。Java で書かれたプログラムは **Java バイトコード**と呼ばれるものにコンパイルされ、これが配布されるバイナリ/実行ファイルになります。このバイトコードは、そのプログラミング言語独自のマシンコード/コンパイル済みコードだと考えられます。ただし、これは実際のネイティブなマシンコードでは*ありません*。このバイトコードはシステムには理解できないので、バイトコードをマシンコードに変換するものが必要です。Java プログラムを実行するには「Java をインストール」(具体的には **Java Runtime Environment (JRE)**)する必要があり、これがバイトコードの変換機能を提供します。この変換機能が、バイトコードをマシンコードに変換します。プログラムが実行されると、バイトコードは JRE の一部である **Java Virtual Machine (JVM)** によって解釈されます。JVM がバイトコードを解釈するとき、バイトコードをマシンコードに変換し、それが*その後で*ネイティブに実行されます。このようなコンパイルと実行を行うコンパイラーは、**Just-In-Time (JIT)** コンパイラーと見なされます。この種の言語には、ユーザーがインタープリターをインストールしていれば、どのアーキテクチャでも実行できるので、移植性があるという利点があります。もちろん、インタープリター自体はアーキテクチャ固有のものに*なります*。

.NET は Java に似ています。ちなみに、.NET は多くの言語で構成されていますが、C# は「*the*」.NET 言語です。.NET は **Microsoft Intermediate Language (MSIL)** にコンパイルされますが、これはバイトコードそのものです。このバイトコードは、.NET Framework の一部によって実行されます。ここで言う .NET Framework の一部とは、**Common Language Runtime (CLR)** のことです。CLR には、ガベージコレクション、セキュリティ関連の機能、JIT コンパイラーが含まれます。この JIT コンパイラーは、Java Runtime Environment (JRE) と同じように、バイトコードをマシンコードに解釈します。前に述べたとおり、.NET はコンパイルと実行の仕方が Java とよく似ています。  
この種の言語のもう 1 つの大きな利点はセキュリティです。すべてが何らかの VM を通して実行されるので、VM がさまざまなセキュリティチェックや管理を行えます。ガベージコレクションは大きな利点なので、改めて強調しておきます。ガベージコレクションは、開発者の仕事を楽にしつつ、メモリ管理も自動的に処理してくれるので、セキュリティにも良いのです。

Java や C# はコンパイル型だと考える人がいる一方で、Python はインタープリター型だと呼ぶ人もいます。これは、言語がどう動くか、あるいはむしろ、どう動くと思われているかによります。Python は実際にはバイトコードにコンパイルされるので、Java や .NET とよく似ています。このバイトコードは、Java や .NET と同様に VM によって解釈されます。つまり実際には、それほど違いはありません。人々が Python をコンパイル型だと考えないのは、実行ファイルがなく、.py のスクリプトだけがあるからです。C# や Java では、少なくとも何らかの形の実行ファイルがあります。
